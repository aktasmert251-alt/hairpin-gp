# Logging and retention

The application keeps full remote addresses only in memory for connection limits and abuse protection. The `badMessage`, `helloTimeout`, `wsFlood` and `messageError` events log 12-character salted SHA-256 network tags through `server/src/privacy.ts`, never readable prefixes. The hash input is the IPv4 /24 or IPv6 /64 network; IPv4-mapped addresses are normalised by the transport. The random log salt changes at every process restart. Message errors retain only the error class. Nicknames appear in public room listings (owner) and in the admin player monitor; they are not persisted as player profiles.

Bans use a random browser device identifier and optionally a full salted network hash, with a separate persistent admin salt. Ban records and audit files are held in the configured private server data directory; bans remain until expiry or admin removal. The admin AuditLog removes audit day files older than 14 days on writes; journal retention is configured below. Browser site-data deletion removes the local device identifier and settings.

Copy `retention.conf` beside `setup.sh` on the VM before running setup. Setup installs it as `/etc/systemd/journald.conf.d/60-hairpin-retention.conf`, restarts journald, rotates the journal and vacuums archives older than 14 days. `MaxRetentionSec=14day` bounds archived journal retention; `MaxFileSec=1day` rotates active files daily. Expiry is at file granularity during rotation, not per-record deletion at exactly 14 days. This applies to **all journals on this dedicated VM**, including non-game system services. Inspect the effective configuration with `systemd-analyze cat-config systemd/journald.conf` and application logs with `journalctl -u apex`.

The static game distribution includes `/THIRD-PARTY-LICENSES.txt`, `/data/tracks/README.md`, `/legal/privacy.html` and `/legal/terms.html`. The deploy archive includes the distribution and therefore the notices (including ws MIT). No server setup or deployment was performed as part of the local change. The main-menu Contact form replaces the former contact-address placeholder. Messages are read but not answered.


D-055 feedback is stored in DATA_DIR/contact.jsonl with mode 600, capped at 2 MiB. Records expire after 30 days; startup, hourly and access-time pruning remove expired entries. Do not back up this file into longer-lived archives. No device id, network hash or raw IP is stored with messages. Payloads never enter operational or audit logs. Spam limits are 5 messages/device/hour and 20/network/hour; counters use process-local salted hashes and reset on restart. The inbox reuses admin sessions, Origin and CSRF checks. Deploy with HTTPS. CONTACT_ORIGINS is an optional comma-separated exact origin allowlist for trusted desktop/file or separate web builds (use null explicitly for a trusted file build); it does not change admin API rules. Default contact access is same origin only.
